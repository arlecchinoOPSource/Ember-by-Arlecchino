# Ember startup screen and cue

Issue #18 uses the neutral `StartupScreen` in `@arlecchino/suite-ui`, derived from Terminal's startup view. Ember supplies its own wordmark, orange theme and habit-loading messages. The screen reflects the three local SQLite reads required to open the month; it disappears as soon as they succeed. A failed read reveals the existing `LOAD ERROR` and **Retry loading** controls. Any key or click skips the visual screen, while the underlying load continues. The screen also leaves after ten seconds so a stalled read does not hide the loading state indefinitely.

The startup screen and startup sound default to **On** for a new installation. Existing device preferences, including an explicit Off choice, are preserved under `ember.preferences.v1`. Changing the screen preference applies on the next launch. Full motion keeps the title page visible for the shared Terminal sequence of at least 1.4 seconds after launch, even if the database is ready sooner. Reduced, Off and the operating system's reduced-motion setting remove the visual effect and do not add that hold. A load error or user skip reveals the app immediately. Readiness never waits for the animation to finish. The startup sound has its own switch in the Sounds popup and is independent of the startup screen; see [SOUND-MOTION.md](SOUND-MOTION.md).

`desktop/src/assets/startup.wav` is Arlecchino's six-second Terminal startup recording, copied unmodified at the product owner's explicit request for Ember. Its SHA-256 is `12be25273665b8acfae60ec61101b31d7b0c261136e1addeaad4d0f23193097b`; the source and original author are recorded in Terminal's `docs/AUDIO-ASSETS-v2.0.md`. The other Ember cues are original Ember assets. Playback is attempted once per launch whenever Sound and the Startup switch are on. On macOS it starts natively at process launch; a failed or blocked playback is ignored and cannot delay local data loading.

Startup playback runs at normal speed. Ember also bundles Arlecchino's unmodified Terminal close recording as `desktop/src/assets/close.wav`, with its own Close switch. As in Terminal, closing hides the window as soon as the close sound starts and lets it finish for at most 6.5 seconds; a pending save blocks closing.

The browser preview can exercise startup with synthetic data using `?startupDelay=5600` or `?startupFail=true`; neither parameter is included in the native app. UI tests cover first launch, slow load, keyboard skip, retry, preference persistence and audio rejection. Offline startup and cue playback in installed macOS and Windows bundles still require platform verification before issue #18 or the 2.0 release is marked complete.
